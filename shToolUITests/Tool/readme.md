# Tool 目录说明

本目录位于 `shToolUITests/Tool/`，是一套面向 **Atlas 自动化测试系统** 的工程辅助脚本与资源集合。覆盖场景包括：Atlas2 环境的启动与组件安装、Schooner 测试序列编译、机台（Fixture）动作与 RPC 控制、多台 MIX 设备的文件同步与更新、测试日志监控等。

---

## 各模块功能说明

### 1. 顶层脚本

| 文件 | 功能 |
|------|------|
| `Common.sh` | 命令行交互菜单。提供 查看当前文件夹结构 / 打印 SSH 公钥 / 实时系统监测（CPU、内存、磁盘、网络），以及微信双开等工具函数。 |
| `CurrentTestFail.sh` | 循环监控 `~/Library/Logs/Atlas/active/group*/system/records.csv`，按 Group 聚合提取 `,FAIL,` 记录（含 SN、行号、失败内容），输出到终端与 `~/Desktop/fail_monitor.log`。兼容 macOS Bash 3.x。 |
| `SchoonerCompile.sh` | 触发 Schooner 序列编译：先备份 `~/Library/Atlas2`，调用 `AtlasLua BuildSchoonerSequence.lua` 依据 MainTable/LimitsTable/ConditionTable 生成 `coverage.lua`。 |
| `SchoonerCompile2.sh` | SchoonerCompile 的增强版：增加 “测试条件错误自动修复”逻辑——检测到 `Test Condition:xxx is not generated by any test` 时自动删除 LimitsTable 中的对应行并重试编译（最多 10 次）。 |
| `SchoonerCompiler-new` | 更完善的 Schooner 编译脚本：自动识别 Mac 架构（arm64/x86_64），必要时用 `arm64/` 或 `x86_64/` 下对应版本替换 `mooncake_0.so`；备份、生成 compiler plist（`Assets/Coverage/SchoonerCompilerArgs.plist`）、编译后执行 `xattr -rc` 去除隔离属性。 |
| `start_Atlas2` | 打开/启动 AtlasRecordsUI.app 与 AtlasUI.app（附带可选注释掉的 launchctl 卸载、清理、station 配置替换等步骤）。 |
| `auto` | 配置 shTool 开机自启动：自动定位 `com.sc.appauto.plist`，用 PlistBuddy 替换 `ProgramArguments` 的 app 路径，复制到 `~/Library/LaunchAgents`，执行 `launchctl unload/load`，并 `killall shTool` 重启。 |
| `com.sc.appauto.plist` | LaunchAgent 模板：KeepAlive + RunAtLoad 方式拉起 shTool.app。 |
| `Version` | 变更/版本笔记（纯说明文字，非可执行程序）。 |

### 2. `arm64/`、`x86_64/`
存放 Mooncake（Atlas 的 Lua 扩展加载器）针对不同 CPU 架构的二进制资源：
- `mooncake_0.so`：各架构的 C 扩展动态库
- `mooncake.lua`：Lua 封装（加载 `mooncake_0.so`，实现 `json_schema`/`failsafe_schema`/`core_schema` 等标量类型解析）

配合 `SchoonerCompiler-new` 在编译时按本机架构自动选用。

### 3. `Common/` — Atlas2 环境初始化辅助
| 文件 | 功能 |
|------|------|
| `setup` | 首次部署脚本：用 `mysides` 给 Finder 侧边栏添加快捷入口（Library / AtlasLog / tools / vault）、创建日志目录与软链、安装 Atlas2CSV 插件、通过 `BigHonkingText` 弹绿色横幅提示。 |
| `start_Atlas2` | 同顶层 `start_Atlas2`，并额外添加侧边栏快捷方式。 |
| `ColorBlink` | 循环调用 `BigHonkingText`，让一个苹果符号在不同颜色下上下跳动滚动动画。 |
| `mysides` | x86_64 可执行程序，Apple 侧边栏管理工具（来源：macos-filesystem/sides）。 |
| `BigHonkingText` | x86_64 可执行程序，在屏幕指定位置显示超大横幅文字（支持透明度、高度、位置、颜色）。 |

### 4. `mix/` — 多台 MIX 机台管理
| 文件 | 功能 |
|------|------|
| `main` | 入口菜单（旧版）。按 “数字N / A+数字N” 选择通道，映射到 `111.111.111.{31+slot}` 的 IP。支持 chmod、推送文件到 MIX、拉取 log、拉取整个 mix 文件夹、更新 mixbundle。内部通过 `osascript` 打开新终端窗口分别执行子脚本。|
| `MIX` | 入口菜单（新版/Shell 版）。通过 `ip_selector.scpt` / `ip_selector_tk.py` 弹出 IP 多选列表，按通道执行相同的 chmod/推送/拉取/更新功能。 |
| `Update` | zsh 脚本：校验网络连通后调用 `mix -e <网卡> -i <IP> -f <mixbundle>` 远程更新指定通道的 mixbundle。 |
| `auto_scp.sh` | expect 脚本：SSH 登录 MIX（mix7/mix8 自动识别不同账号密码），对单个文件或整个文件夹递归删除并上传到远程 `/mix`，可选重启 mix 服务（`-R/-r/-y/-Y`）。 |
| `auto_scp_get.sh` | expect 脚本：从 MIX 的 `/mix` 或 `/var/tmp/mix` 等路径 SCP 拉取文件到本地并自动打开。 |
| `chmod.sh` | expect 脚本：SSH 登录后 `sudo chmod -R 777 /mix`（区分 mix7/mix8 账号密码）。 |
| `get_file_paths.sh` | 通过 `osascript` 弹出原生对话框（可拖拽）获取一个或多个文件路径，标准化为路径数组返回。 |
| `ip_selector.scpt` | AppleScript 原生列表选择器，生成 `111.111.111.32~39` IP 列表，支持多选，输出逗号分隔结果。 |
| `ip_selector_tk.py` | Python tkinter 版 IP 选择器，作为 `.scpt` 的备用实现。 |

### 5. `rsync/` — 跨电脑同步
| 文件 | 功能 |
|------|------|
| `JSYNC-PUSH` | 批量同步 `ZJX_backup/` 到多台电脑（rsync 增量 + `--delete`），然后 SSH 过去 `killall shTool` 并重新 `open .../Tool/auto` 启动，并拷贝 MIX-Tool。 |
| `JSYNC-PUSH_33` | 同步到单台电脑（10.8.30.33）+ 重启 shTool 的版本。 |
| `JSYNC-GET_14` | 从远程电脑的指定路径拉取文件到本地 `Test/` 目录。 |
| `demo_push` / `demo_get` | rsync 最小用法示例：推送到/拉取自 10.8.30.33。 |

### 6. `RPC_/` — RPC / 机台控制（Atlas Lua）
| 文件 | 功能 |
|------|------|
| `RPC`（bash） | 调用 `AtlasGroupProcess coreless ./RPC.lua` 的入口包装脚本，结束后自动关闭窗口。 |
| `RPC.lua` | 提供基于 `MIXRPCRelay` 插件的 RPC 能力：JSON 序列化、日志记录、`RPC_init/RPC_send/RPC_close`、`slot_reset`，以及写 FixtureSN、DOE 电源动作、系统性校准写入（`write_cal/write_cal2/write_doe`）等高阶函数；底部含正则匹配调试代码。 |
| `FixtureContro`（bash） | 调用 `AtlasGroupProcess coreless ./FixtureContro.lua` 的入口包装脚本。 |
| `FixtureContro.lua` | 机台控制核心：LED 状态（`setLed`）、托盘进出/上下、传感器读取（`readTraySensor`/`readThroughSensor`）、磁铁开关、`press`/`release`/`T_in`/`T_out` 等动作，配合 `helper.lua` 日志与 `mutex.lua` 锁机制。 |
| `FixtureControl_SC`（bash） | 新电控板（SC 方案）控制脚本的入口包装：调用 `AtlasGroupProcess coreless ./FixtureControl_SC.lua`，结束后自动关闭窗口。 |
| `FixtureControl_SC.lua` | 基于 `FixtureControl_SC` 插件（较新的电控板控制方式）的串口调试/控制脚本。加载插件后用 `action_init` 初始化串口（默认 `/dev/cu.usbserial-ECB`），通过指令分发 `dispatch()` 支持 `in`/`down`/`press`/`out`/`up`/`release`/`startbutton`/`led <1-8> <R/G/B/Y>`/`ledreset`/`read(传感器状态)`/`send <cmd>` 等命令；支持“读 `/tmp/FixtureControlCore.txt` 文件指令单次执行”与“交互式命令行”两种模式。 |
| `helper.lua` | 日志辅助模块：分级日志（Debug/Info/Error）、带线程/文件前缀的格式化输出、table 递归打印。 |
| `mutex.lua` | 互斥锁封装：基于 Atlas `MutexPlugin` 的 `runWithLock`/`reset`/`isNewIdentifier`，用 `/dev/urandom` 生成 UUID。 |
| `ZJX/CommonFunc.lua` | 通用文件读写、获取用户、弹系统对话框（osascript）等工具函数。 |
| `ZJX/RPC.lua` | RPC.lua 的模块化封装：`require` CommonFunc，导出 `RPC` 表，提供 `log_init`/`RPC_init`/`RPC_send`/`RPC_close` 等。 |

### 7. `Lua_RPCClient/` — 多设备 RPC 客户端测试框架
| 文件 | 功能 |
|------|------|
| `Panda.lua` | 测试执行主脚本：通过 TCP/`MIXRPCRelay` 连接设备，支持 `sequential`/`coroutine`（协程并行）两种运行模式；动作包括 `getInfo`、`measure`、`sleep`；从 `MainTable.csv` 读取测试计划，自动做上下限判定（limits 检查），结果写入 `records.csv` 并输出 `panda.log`，含 PASS/FAIL 统计与错误采样。 |
| `MainTable.csv` | 测试计划配置表：`Disable, testName, action, command, lowerLimit, upperLimit, units`。 |
| `test.lua` | 对 `lfs`/`llthreads` Lua 扩展库的环境验证示例。 |
| `README.md` | 该子模块自带的详细说明（功能、配置、字段说明等）。 |

## 运行环境与依赖
- **macOS + Bash/Zsh**：大部分脚本为 Bash 脚本，`mix/Update` 为 zsh 脚本。
- **Atlas / Atlas2**：依赖 `~/Library/Atlas2`、`AtlasLua`、`AtlasGroupProcess`、`MIXRPCRelay`、`MutexPlugin` 等 Atlas 组件或运行时注入。
- **expect**：`auto_scp.sh`、`auto_scp_get.sh`、`chmod.sh`、`rsync/*` 使用 `spawn/expect` 做 SSH/SCP 自动化。
- **Lua / Lua 扩展库**：`Panda.lua` 等需 `MIXRPCRelay` 插件，并依赖 `socket`、`lfs`、`llthreads`、`cjson` 等 `.so` 扩展（见 `Lua_RPCClient/README.md`）。
- **Python3**：`ip_selector_tk.py`、毫秒时间戳生成。
- **Apple 辅助工具**：`BigHonkingText`、`mysides`（x86_64 可执行）。

> 注：多数脚本内嵌了具体项目相关的 IP、账号密码与路径，为内部测试辅助工具，仅供了解与该测试团队内复用。

## 注意事项
- `mix/main` 的菜单 `case 4` 同时绑定了“拉取 MIX 文件夹”和“更新 mixbundle”两项（第 287 行重复分支），实际以第一个 `4)` 为准，更新 mixbundle 建议改用 `mix/MIX`。
- 各脚本中的 IP / 密码 / 路径均为实际工程配置，使用前请按当前项目自行调整。
- `CurrentTestFail.sh` 的 `TOTAL_DURATION` 被设置成一个极大值，等同于持续监控。
